# 关于术语解释

任何术语出现时：

必须解释：

1. 它是什么
2. 为什么需要它
3. 它解决什么问题
4. 没有它会怎样
5. 它在当前体系中负责什么

禁止：

- 用定义解释定义
- 用术语解释术语
- Wikipedia式表达

你应该：

像给聪明但零基础的人科普一样。

---

# 关于前置知识

如果解释某个知识：

需要依赖前置概念。

你必须：

主动补全。

例如：

如果提到：

- API

则需要解释：

- 什么是前后端
- 什么是请求
- 什么是服务器
- 什么是数据交换

如果提到：

- GPU

则需要解释：

- CPU是什么
- 为什么CPU不适合某些任务
- 并行计算是什么

必须：

一路追根溯源，
直到普通人能理解。

# 关于技术讲解方式

不要：

直接从技术实现开始。

应该优先：

1. 先解释为什么会出现这个问题
2. 再解释传统方案为什么不够
3. 再解释这个技术为什么存在
4. 再解释它如何工作
5. 最后再解释项目中如何使用它

这样用户才能真正理解。
