# 代码修改规范

## 核心原则

1. **读取 design.md** — 修改前必须先读取项目的 design.md，了解项目约定
2. **最小化修改** — 只改必要的部分，不重构无关代码
3. **模式复用** — 识别现有代码模式，新代码必须遵循相同模式
4. **风格一致** — 颜色/间距/组件用法与现有代码完全一致

## 文件定位策略

从用户描述中提取目标文件：

| 用户描述 | 定位方式 |
|---------|---------|
| "给用户管理增加..." | 搜索 `src/views/` 下包含"用户"的 Vue 组件 |
| "修改登录页面" | 搜索 `src/views/` 下包含"login"的 Vue 组件 |
| "这个按钮没反应" | 需要用户提供页面名称或文件路径 |
| `/api/xxx/yyy` | 通过 API 路径反向查找对应的页面 |

## 代码插入位置规则

| 要添加的内容 | 插入位置 |
|-------------|---------|
| 操作按钮 | `el-row :gutter="10" class="mb8"` 内，`<el-col :span="1.5">` 中 |
| 表格列 | `el-table` 内，按业务逻辑顺序插入 |
| 搜索条件 | `el-form :model="queryParams" :inline="true"` 内 |
| 表单字段 | `el-dialog` 或页面表单的 `el-form` 内 |
| 方法 | `methods` 对象内，按功能分组 |
| 数据字段 | `data()` 对象内，按功能分组 |
| 生命周期钩子 | `created()` 或 `mounted()` 内 |

## 代码风格检查清单

修改后的代码必须满足：

- [ ] 使用 design.md 中定义的全局方法（如 `$modal.msgSuccess` 而非 `$message.success`）
- [ ] 使用 design.md 中定义的全局组件（如 `<pagination>` 而非 `<el-pagination>`）
- [ ] 使用 design.md 中定义的指令（如 `v-hasPermi`）
- [ ] 颜色使用 SCSS 变量，不硬编码
- [ ] 间距使用项目现有的间距系统
- [ ] 深度选择器使用 `::v-deep`
- [ ] 样式使用 `<style lang="scss" scoped>`
- [ ] ESLint 规则：缩进、引号、分号与项目一致

## 修改后验证

1. 检查新代码是否与周围代码风格一致
2. 检查是否使用了正确的全局方法和组件
3. 检查是否遗漏了权限指令
4. 检查是否引入了语法错误
